# RFC-0005

# Modelo de Dados Detalhado
## (DDL Proposto + Estratégia de Migração)

**Status:** Draft
**Autor:** Arquitetura
**Data:** 2026-02-24
**Depende de:** RFC-0001, RFC-0002, RFC-0003, RFC-0004

---

# 1. Contexto

Este RFC define:
* Modelo relacional inicial
* Estrutura de tabelas do MVP
* Índices obrigatórios
* Estratégia de versionamento de schema
* Preparação para evolução multi-tenant
* Estratégia de migração futura (schema por tenant / banco por tenant)

Banco alvo: PostgreSQL.

---

# 2. Princípios de Modelagem

1. Toda tabela multi-tenant deve conter `organization_id`
2. Nunca confiar apenas em constraints de aplicação
3. Índices devem refletir padrões de acesso reais
4. AttendanceRecord é imutável
5. Biometria deve ser referenciada, nunca embutida
6. Preparar colunas para auditoria desde o início

---

# 3. Convenções

* UUID como chave primária
* `created_at` e `updated_at` em UTC
* `server_received_at` obrigatório para registros críticos
* Soft delete apenas onde necessário
* Nunca deletar registros de presença

## 4.1 organization
```sql
CREATE TABLE organization (
id UUID PRIMARY KEY,
name VARCHAR(255) NOT NULL,
created_by VARCHAR(64) NOT NULL,
created_at TIMESTAMP NOT NULL,
status VARCHAR(32) NOT NULL DEFAULT 'ACTIVE'
);
Índice:
CREATE INDEX idx_org_created_by ON organization(created_by);

4.2 unit
CREATE TABLE unit (
id UUID PRIMARY KEY,
organization_id UUID NOT NULL,
name VARCHAR(255) NOT NULL,
geo_type VARCHAR(16) NOT NULL, -- RADIUS | POLYGON
geo_center_lat DOUBLE PRECISION,
geo_center_lng DOUBLE PRECISION,
geo_radius_meters INTEGER,
geo_polygon JSONB,
created_at TIMESTAMP NOT NULL,
FOREIGN KEY (organization_id) REFERENCES organization(id)
);
Índice:
CREATE INDEX idx_unit_org ON unit(organization_id);

CREATE TABLE membership (
id UUID PRIMARY KEY,
organization_id UUID NOT NULL,

status VARCHAR(32) NOT NULL DEFAULT 'ACTIVE',
joined_at TIMESTAMP NOT NULL,
FOREIGN KEY (organization_id) REFERENCES organization(id)

CREATE UNIQUE INDEX uq_membership_user_org
ON membership(user_id, organization_id);

4.6 attendance_record
IMUTÁVEL.
CREATE TABLE attendance_record (
id UUID PRIMARY KEY,
organization_id UUID NOT NULL,
unit_id UUID NOT NULL,
user_id VARCHAR(64) NOT NULL,
latitude DOUBLE PRECISION NOT NULL,
longitude DOUBLE PRECISION NOT NULL,
gps_accuracy DOUBLE PRECISION NOT NULL,
biometric_score DOUBLE PRECISION,
biometric_valid BOOLEAN,
device_id VARCHAR(128) NOT NULL,
registration_mode VARCHAR(16) NOT NULL, -- SELF | SHARED_DEVICE
intermediary_user_id VARCHAR(64),
risk_score DOUBLE PRECISION,
risk_flags JSONB,
technical_status VARCHAR(32) NOT NULL DEFAULT 'RECEIVED', -- Recebido, Processado, Rejeitado, etc.
administrative_status VARCHAR(32) NOT NULL DEFAULT 'PENDING', -- Válido, Pendente de Justificativa, Ignorado, etc.
captured_at TIMESTAMP NOT NULL,
server_received_at TIMESTAMP NOT NULL,
FOREIGN KEY (organization_id) REFERENCES organization(id),
FOREIGN KEY (unit_id) REFERENCES unit(id)
);
Índices críticos:
CREATE INDEX idx_attendance_org_user
ON attendance_record(organization_id, user_id);

CREATE INDEX idx_attendance_org_time
ON attendance_record(organization_id, server_received_at);

CREATE INDEX idx_attendance_unit_time
ON attendance_record(unit_id, server_received_at);

4.10 relationship

CREATE TABLE relationship (

4.11 user_permissions_override
Tabela responsável por permitir granularidade de acessos e permissões de exceção individuais baseadas em políticas dinâmicas (PBAC / ABAC) sem inflar a tabela de roles principais, garantindo autonomia sobre as regras fora do Keycloak.
CREATE TABLE user_permissions_override (
id UUID PRIMARY KEY,
organization_id UUID NOT NULL,
user_id VARCHAR(64) NOT NULL,
resource VARCHAR(128) NOT NULL, -- Ex: '/presencas', 'relatorios'
scope VARCHAR(64) NOT NULL, -- Ex: 'view', 'approve'
condition_json JSONB, -- Ex: {"policy": "somente_unidade", "unidade_id": "xyz"}
created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
FOREIGN KEY (organization_id) REFERENCES organization(id)
);
Índices:
CREATE INDEX idx_permissions_org_user
ON user_permissions_override(organization_id, user_id);
